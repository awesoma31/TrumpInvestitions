# Тестирование

#dev #testing #go #kotlin

## Структура тестов

| Тип | Команда | Что покрывает |
|---|---|---|
| Unit | `make test-unit` | Бизнес-логика без зависимостей |
| Integration | `make test-integration` | Сервисы с реальными БД |
| Gateway | `make test-gateway` | E2E через auth-gateway |
| All | `make test-all` | Всё вместе |

## Юнит-тесты

### Go-сервисы

```bash
# market-data-service
cd market-data-service && go test ./...

# portfolio-service
cd portfolio-service && go test ./...

# trading-service
cd trading-service && go test ./...
```

Покрывают:
- Логику расчёта P&L
- Логику исполнения ордеров (моки market-data)
- Пересчёт avg_price при усреднении позиции
- Валидацию входных данных

### auth-gateway (Kotlin)

```bash
cd auth-gateway && ./gradlew test
```

Покрывают:
- JWT генерацию и валидацию
- BCrypt хэширование
- Логику маршрутизации

## Интеграционные тесты

Требуют запущенной инфраструктуры:

```bash
# Поднять только инфраструктуру
docker compose up -d postgres clickhouse kafka

# Запустить интеграционные тесты
make test-integration
```

> [!warning] Два теста падают
> На данный момент 2 интеграционных теста помечены как `#TODO` и известно, что они не проходят. Это известная проблема.

## Gateway-тесты (E2E)

Требуют полностью запущенного стенда:

```bash
# Запустить все сервисы
make up

# Запустить E2E тесты
make test-gateway
```

Сценарии:
1. Регистрация → логин → получение котировок
2. Пополнение счёта → создание ордера → проверка портфеля
3. Попытка доступа без токена → 401

## Тестовые данные

[[pricing_engine]] загружает синтетические данные для 5 инструментов:
`AAPL`, `MSFT`, `TSLA`, `BTC/USDT`, `ETH/USDT`

Данные воспроизводимы (фиксированный seed) — подходят для assertions в тестах.

## CI статус

Тесты запускаются в GitHub Actions при каждом PR. Конфигурация в `.github/workflows/`.
