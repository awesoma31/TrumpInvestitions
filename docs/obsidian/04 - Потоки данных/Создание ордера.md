# Создание ордера (end-to-end)

#flow #trading #sequence #critical-path

Главный бизнес-сценарий платформы: пользователь покупает/продаёт актив.

## Полный sequence diagram

```mermaid
sequenceDiagram
    actor C as 📱 Client
    participant AG as auth-gateway
    participant TS as trading-service
    participant MDS as market-data-service
    participant PG_T as PostgreSQL (trading)
    participant K as Kafka
    participant PS as portfolio-service
    participant PG_P as PostgreSQL (portfolio)

    C->>AG: POST /api/v1/trading/orders<br/>Authorization: Bearer JWT<br/>{symbol:"AAPL", side:"BUY", type:"MARKET", quantity:"10"}

    AG->>AG: Валидация JWT → userId
    AG->>TS: POST /api/v1/orders<br/>X-User-Id: <userId>

    TS->>MDS: GET /api/v1/quotes/AAPL
    MDS->>MDS: SELECT last quote FROM ClickHouse
    MDS-->>TS: {ask_price:"150.30", bid_price:"150.25", ask_size:"500"}

    TS->>TS: Проверить ask_size >= quantity (500 >= 10 ✓)
    TS->>TS: Цена исполнения = ask_price = 150.30<br/>gross_amount = 10 × 150.30 = 1503.00

    TS->>PG_T: INSERT INTO orders (id, user_id, symbol, side, quantity, status=NEW)
    PG_T-->>TS: OK

    TS->>PG_T: UPDATE orders SET status=FILLED, avg_fill_price=150.30
    TS->>PG_T: INSERT INTO trades (order_id, price, quantity, gross_amount)
    PG_T-->>TS: OK

    TS->>K: PRODUCE trading-events<br/>{event_type:"ORDER_FILLED", order_id, user_id,<br/>symbol:"AAPL", side:"BUY", quantity:"10", price:"150.30"}
    K-->>TS: ACK

    TS-->>AG: 201 {order_id, status:"FILLED", avg_fill_price:"150.30"}
    AG-->>C: 201 (ответ клиенту)

    Note over K,PS: Асинхронно
    K->>PS: CONSUME trading-events

    PS->>PG_P: UPDATE portfolios<br/>SET cash_balance = cash_balance - 1503.00
    PS->>PG_P: UPSERT positions<br/>quantity += 10, пересчёт avg_price
    PG_P-->>PS: OK
    PS->>K: COMMIT offset
```

## Сценарий SELL

Отличается от BUY в следующих шагах:
1. Цена исполнения = `bid_price` (не `ask_price`)
2. portfolio-service: `cash_balance += gross_amount`
3. portfolio-service: `positions.quantity -= quantity`
4. portfolio-service: `positions.realized_pnl += (price - avg_price) × quantity`

## Сценарий: ордер отклонён

```mermaid
sequenceDiagram
    participant TS as trading-service
    participant MDS as market-data-service
    participant PG_T as PostgreSQL
    participant K as Kafka

    TS->>MDS: GET /quotes/AAPL
    MDS-->>TS: {ask_size: "5"}

    TS->>TS: ask_size (5) < quantity (10) — нет ликвидности

    TS->>PG_T: INSERT orders (status=NEW)
    TS->>PG_T: UPDATE orders SET status=REJECTED
    TS->>K: PRODUCE {event_type:"ORDER_REJECTED", reason:"NO_LIQUIDITY"}
    TS-->>AG: 422 {status:"REJECTED", reason:"NO_LIQUIDITY"}
```

## Временные характеристики

| Шаг | Ожидаемое время |
|---|---|
| Валидация JWT | ~1 ms |
| Запрос котировки | ~15 ms |
| Запись в PostgreSQL | ~5-10 ms |
| Публикация в Kafka | ~3-5 ms |
| **Итого (синхронная часть)** | **~25-35 ms** |
| Обновление портфеля (async) | ~10-20 ms |
